## 📋 测试前的准备

### ✅ 必需
```
1. 后端服务启动并运行
2. 数据库已初始化
3. 测试账号已创建 (admin/8888, manager/8888 等)
4. 现代浏览器 (Chrome/Safari/Firefox)
```

### ⚠️ 常见问题

**Q: 没有后端服务，能测试什么？**
```
A: 可以测试:
  ✅ 前端 UI 是否正确显示
  ✅ 表单验证是否有效
  ✅ 页面路由是否正常
  ✅ localStorage 机制
  
  需要后端的:
  ❌ 实际登录
  ❌ 用户管理操作
  ❌ 权限验证
```

**Q: 登录失败，怎么排查？**
```
1. 打开浏览器开发者工具 (F12)
2. 点击 Network 标签
3. 尝试登录
4. 查看 POST /api/user/login 请求
5. 检查响应状态码与内容
```

**Q: 功能看起来有问题，怎么报告？**
```
1. 在 test-quick.html 右下角查看调试信息
2. 检查浏览器控制台 (F12 → Console)
3. 查看 localStorage 内容
4. 记录错误信息与步骤
5. 参考 TESTING_CHECKLIST.md 中的 Bug 记录表
```

## 🔧 测试场景详解

### 场景 1: 测试用户认证 (必需后端)
```
步骤:
1. 打开 login.html
2. 输入用户名: admin
3. 输入密码: 8888
4. 点击登录

预期结果:
✅ 页面跳转到 index.html
✅ 导航栏显示用户名 "admin"
✅ localStorage 中有 auth_token
✅ 可以访问所有功能
```

### 场景 2: 测试权限检查
```
步骤:
1. 以 admin 登录 → 可以看到所有菜单项
2. 以 operator 登录 → 看不到"管理"菜单
3. 以 viewer 登录 → 看不到任何管理功能

预期结果:
✅ 不同角色看到不同的菜单
✅ 禁用的按钮无法点击
✅ 权限检查正常工作
```

### 场景 3: 测试用户管理
```
步骤 (需要 admin 角色):
1. 点击"用户管理"菜单
2. 点击"创建新用户"按钮
3. 填入用户信息
4. 点击保存
5. 检查用户是否添加到列表

预期结果:
✅ 表单验证有效
✅ 新用户出现在列表中
✅ 可以编辑和删除用户
```

### 场景 4: 测试审计日志
```
步骤 (需要 admin 角色):
1. 点击"审计日志"菜单
2. 查看日志列表
3. 尝试过滤日志
4. 点击"详情"查看变更信息
5. 点击"导出日志"下载 CSV

预期结果:
✅ 日志列表显示
✅ 过滤功能有效
✅ 详情页面显示变更前后值
✅ CSV 文件可下载
```

### 场景 5: 测试访客管理
```
步骤 (需要 admin 角色):
1. 点击"访客管理"菜单
2. 点击"创建访客账号"
3. 填入访客信息，设置 7 天有效期
4. 选择"只读"权限
5. 保存
6. 在列表中找到新访客

预期结果:
✅ 访客账号创建成功
✅ 有效期显示正确
✅ 权限等级显示正确
✅ 可以编辑和删除访客
```

### 场景 6: 测试会话管理
```
步骤:
1. 打开多个浏览器标签页
2. 在第 1 个标签页登录
3. 在第 2 个标签页登录（同一账号）
4. 在第 3 个标签页尝试登录
5. 注意哪个标签页被登出

预期结果:
✅ 同账号最多 5 个标签页
✅ 超过 5 个时最早的被登出
✅ 一个标签页登出其他同步
```
