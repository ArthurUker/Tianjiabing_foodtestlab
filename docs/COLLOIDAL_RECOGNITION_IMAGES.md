# 识别过程标注图与 CodeBuddy 接续

2026-10-22。用户要求在系统过程日志中直接查看算法在原图里定位到了哪里。本轮沿用固定v5/geom1及真实日志坐标，增加可视化；不是窗口定位修复，不改变C/T阈值或判读。

## 使用

检测点位展开“拍照与算法识别过程日志”，再展开对应照片，即可查看“识别过程标注图”。单次记录默认展开；三次采样各有独立图片组。历史记录可点“恢复上次未完成的照片录入”；保存后的记录在详情的“原始照片与结果录入过程”中查看同一组图。旧原图及日志已包含原图坐标时无需重新拍照。

1. 原始照片全景，叠加推算卡位、选定窗口、测量区域、C/T测量线。
2. 推算卡位的局部放大。明确显示“卡壳尚未独立验证”，不是自动找到了真实卡壳。
3. 每个窗口的无标注原图和算法标注对照。三联逐窗口展示，局部预留周边，便于发现框偏到膜窗外。手机竖屏上下排列并有单独图名。

黄虚线=定位板推算卡位；绿框=算法选定观察窗；青框=实际测量区域；紫线=C测量位置；红线=T测量位置。线位只是算法采样位置，不表示确实检出了色带。所选检测通道名称不表示已通过图像独立确认产品身份。每张图可下载PNG；文字及坐标日志保留为可展开区，JSON仍可下载。

没有窗口坐标时明确说明缺失，不根据固定卡位补画窗口或C/T。旧日志缺坐标、原图已清理或浏览器不能解码时保留明确提示。浏览器解码尺寸与日志不同则只显示原图，停止叠加，避免制造坐标错位。

## 实现与数据边界

- `frontend/js/colloidal/RecognitionImages.js`：从origin=algorithm且原图坐标空间明确的日志提取几何，浏览器canvas按需绘制。只展示算法原有坐标，包含本次真卡误定位坐标，不重新运行或纠正算法、不输入手工框。
- `ProcessLog.js`优先展示图片；`PhotoEntry.js`在日志无变化时复用原面板，2秒刷新不会反复下载原图或重建图片。记录详情原图与标注共用一次照片请求。
- 新增 `GET /api/colloidal/attempts/:id/photo`：仅当前租户内的检测创建者且具编辑权限可访问，沿用authenticateUser/req.db/attemptOwner。保存后有查看权限的人继续使用原记录照片接口。原图不放静态公开路径，响应private,no-store。
- 继续仅持久化原始上传照片及既有紧凑坐标日志。标注PNG、放大图仅浏览器内存生成，服务器不新增派生图、Base64字段、裁剪像素或磁盘缓存。用户点击下载才保存到用户设备。
- 无新增数据库迁移、Python适配器或核心包变更。之前的过程日志迁移和适配器仍是前提；不能把本说明当作旧版本跳过迁移的依据。

## 服务器接续

先读适用服务器规则、PROJECT_CONVENTIONS.md、COLLOIDAL_PROCESS_LOG.md，核对分支、SHA、dirty工作区、现有迁移及日志适配器状态。备份并按现有流程拉取本轮提交；执行`npm run build:prod`，重启既有Node服务以注册新GET接口。不需要为本轮重装Python或替换固定核心。生产不启用本地免密码preload、局域网证书。

验收：用原失败记录打开标注图，核对框来自日志原图坐标；新拍照/上传、三联、三次采样分别查看；失败不补画，旧/已清理照片提示正确。再查匿名、跨校、非创建者和有权记录查看路径。浏览器控制台、health/readyz、真实手机截图作为证据。不能把界面可画图记为算法修复。失败时回退该可视化版本及Node代码，不删除原图、日志、记录或迁移。
