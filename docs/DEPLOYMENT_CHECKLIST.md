- [ ] 部署窗口已确定
- [ ] 回滚计划已准备
- [ ] 通知已发送

### 部署阶段

**蓝绿部署策略**:

```
当前状态 (蓝)  →  新版本 (绿)  →  切换流量  →  监控  →  清理旧版
```

**部署步骤**:

```bash
1. 部署新版本到绿环境
2. 验证绿环境健康
3. 切换 50% 流量到绿环境
4. 监控 5-10 分钟
5. 切换 100% 流量到绿环境
6. 监控 30 分钟
7. 清理旧版本环境
```

### 部署后验证

**立即验证** (0-5 分钟)

```
- [ ] HTTP 200 OK
- [ ] 首页加载成功
- [ ] 数据库查询正常
- [ ] 错误日志无异常
- [ ] API 响应时间正常
```

**持续验证** (5-30 分钟)

```
- [ ] 错误率 < 0.5%
- [ ] 响应时间 < 400ms (平均)
- [ ] CPU 使用率 < 70%
- [ ] 内存使用率 < 80%
- [ ] 数据库连接 < 50
```

**深度验证** (30+ 分钟)

```
- [ ] 用户登录成功

- [ ] 报表生成成功

```

## 🔧 部署回滚检查 (Rollback)

### 自动回滚触发条件

```
if (错误率 > 5% for 2 minutes) {
  自动回滚到上一个版本
}

if (平均响应时间 > 2s for 2 minutes) {
  自动回滚到上一个版本
}

if (应用崩溃 for 1 minute) {
  自动回滚到上一个版本
}
```

### 手动回滚步骤

```bash
1. 停止新版本应用
2. 恢复数据库备份 (如需要)
3. 启动旧版本应用
4. 切换流量回到旧版本
5. 验证系统恢复正常
6. 通知相关团队
7. 分析问题原因
```

## 📊 性能基准测试

### 基准指标

| 指标 | 目标 | 阈值 |
|------|------|------|
| 首页加载 | < 1.5s | 超过则告警 |
| API 响应 | < 400ms | 超过则告警 |
| 错误率 | < 0.1% | 超过则告警 |
| 缓存命中 | > 80% | 低于则告警 |
| CPU 使用 | < 70% | 超过则告警 |
| 内存使用 | < 80% | 超过则告警 |
| 磁盘 I/O | < 70% | 超过则告警 |

### 性能测试脚本

```bash
#!/bin/bash

# 首页加载时间
curl -w "@curl-format.txt" -o /dev/null -s http://api.example.com/

# API 响应时间
for i in {1..100}; do
  curl -w "%{time_total}\n" -o /dev/null -s http://api.example.com/api/data
done | awk '{sum+=$1} END {print "Average: " sum/NR}'

# 错误率测试
ab -n 1000 -c 10 http://api.example.com/api/data
```
