# TPM 单位与阈值 · 待核实资料清单（2026-09-17）

> 目的：把"平台界面标注"与"经设备协议核实的计量结论"分开。**本轮不改数值、不做换算、不重判历史结论。**

## 1. 当前实现事实（代码证据，已核实）

| 事实 | 证据 |
|---|---|

## 2. 尚缺的核实资料（需业务方/设备方提供）

1. **设备型号、固件版本、协议版本**（哪台仪器、哪个协议）。
2. **原始报文样例**（设备输出的字段名、量纲、单位、精度、是否已做温度补偿）。
3. **设备显示值与平台保存值的对照**（同一油样：设备读数 → 录入值 → 平台保存值，至少 5 组）。
4. **阈值的出处与批准记录**（国标/团标/企业内控编号 + 生效日期 + 批准人）。
5. 若设备输出与 `g/100g` **不一致**：换算公式与换算责任方（设备侧 or 平台侧）。

## 3. 核实后的处理原则（预先约定，避免临时改口径）

1. **历史数据不重算**：结论按录入时冻结存储（`conclusion_source='stored'`），不因单位澄清而重判历史记录。
2. **不静默改动 `unit` 语义**：若最终确认单位与现标注不同，采取"新增 `unit_verified:true` + 修订 `unit` + 文档变更记录"，
   并以**新字段**表达换算后的规范值（例如 `tpmValue_standardized`），旧字段保留原义。
3. **对接方沟通**：任何单位/阈值变更都需在接入包中给出"变更说明 + 生效日期 + 影响范围"。

## 5. 影响面与风险

- **对第三方**：单位从"确定"降级为"待核实"——避免其按错误单位做换算（此前表述可能诱导 ×100 或被误当百分比）。
- **对内部指标**：阈值实现未变，**合格率数值不变**；仅表述更保守。
- **残留风险**：若最终核实结果与现标注不同，历史记录的显示口径会存在"两套单位"的过渡期，需按 §3 的约定处理。
