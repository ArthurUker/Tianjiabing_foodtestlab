## 最小验收

全部只用临时文件/受控子进程/合成 secret，不连接 DB、不运行真实 systemd 或 deploy 主流程。

1. **分发负例**：按旧两文件布局缺库、库不可成功加载或缺必需函数，真实入口非零退出；适配文件执行/安装/系统/数据库/git spy 全 0。缺失库不得走到 §5.1 才停。
2. **分发正例**：新文档对应布局可加载正确库；测试在副作用前截停。报告“依赖加载证明”，不称完整部署成功。
3. **成功写回**：调用真实共享写回函数，完整 env 的非 JWT 字段保留，JWT 经真实 dotenv 重载与解析/校验结果字节相等；至少一次含显式 refresh、一次缺省 refresh。第二次部署结果保持，不将随机值或文件内容打印进日志。
4. **失败写回**：注入 fragment 读取失败、组装/输出写入失败、替换失败，分别非零；旧目标 hash 不变，后续步骤/restart spy=0，临时对象清理。故障注入用测试替身/隔离文件条件；不要在真实路径上试验。
5. **后续失败/信号清理**：prepare 成功后模拟既有后续 `exit 1`、INT/TERM；原目标不变，fragment/staging 无残留，退出码合理。只有成功替换之后失败的情况不能承诺回滚旧 env，报告这个边界即可，不新增部署事务/回滚系统。
6. **权限失败**：片段/staging 权限无法建立时非零，无发布/重启，资源清理；正例实际 mode 受限。不要仅断言“调用了 chmod”。
7. 重跑改动涉及的部署 harness/round-trip 与静态检查。已接受 unit 29/29、startup 10/10、Jest 38/40 不必重复；若修改其依赖行为再做对应定点回归并说明。禁止三套 PG 基线重跑。
