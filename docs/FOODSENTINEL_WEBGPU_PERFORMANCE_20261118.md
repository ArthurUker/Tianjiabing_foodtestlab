# 校园食安卫士性能基线与 WebGPU 设计（2026-11-18）

范围是正式业务系统，包括登录后首页、检验看板、检测记录、报告和正式识别页面。手机采集页与只读照片墙属于独立研发工具，不纳入此报告，两个现有服务未重启。校验了照片墙源码与本轮开始时的快照逐字节一致。

用户描述最符合 [Noniv/abyssal-garden](https://github.com/Noniv/abyssal-garden)。它在浏览器内用 WebGPU 生成、渲染海底场景，并按性能动态调整分辨率和绘制范围；有固定镜头路线用于记录帧与 GPU 耗时。可借鉴的是可复现的负载和按设备调整的工作量。业务表单、权限检查、服务端查询与普通 DOM 列表不属于同一种负载。

## 已验证的首屏减负

- 只读检查正式静态首页：`index.html` 仍会提前加载 `html2canvas.min.js` 和 `jspdf.umd.min.js`。生产静态文件在本次 gzip 请求下实际传输 48,984 与 120,392 字节，合计 169,376 字节（约 165 KiB）。本地对应两个文件合计 563,152 字节，未压缩。
- 本地源码移除首页两个脚本标签，第一次导出时才按需请求，重复点击共享加载任务，加载失败可重试。图表库仍按首屏看板需要加载，认证和数据契约未改。第一回导出才承担下载，其后复用。
- 隔离构建运行原 `scripts/build-static.js` 成功；没有替换当前工作区 `dist/`。临时本机 HTTP + 隔离 Chrome 对照：使用同一首页资源集，只切换这两个标签，预览路径（无生产登录会话）首屏资源请求 2→0。以本地 DOM 夹具实际并行执行看板日报、数据报告两个导出路径，总共只下载两文件，生成的两个 Blob 均有 `%PDF-` 签名。33 项现有记录/导出/输出编码相关测试通过。证据见 `.cache/foodsentinel-web-perf-20261118/browser-check.json`。这证明两个资源退出首屏及导出正常，未测生产登录后的整体速度。

## 正式系统分阶段设计

| 阶段 | 做法 | 通过标准 |
|---|---|---|
| 1. 登陆后定瓶颈 | 选一个经授权的学校账号，在同学校、同角色下重复：首页冷开、热开、切换记录页、筛选、导出、识别。记录首屏可用时间、请求数与字节、各接口等待、长任务和主要操作耗时 | 有同路径的中位数和 P95，能区分网络/服务端查询/脚本执行与绘制；不把局域网工具或未登录请求当生产体感 |
| 2. 首页和列表 | 看板目前强制同步多类记录；`StorageService` 默认同步上限每类 1000 行，导出服务初始化也会读取多类记录。先量实际重复和载荷，再考虑按作用域共享在途读请求、看板走带租户与时间范围的服务端摘要、记录页走现有 cursor 分页。表单保留当前权限与学校自定义规则 | 用相同数据检查摘要、时间窗口、权限与跨租户隔离；比较请求量、字节与操作延时；维持缓存与真实覆盖范围语义 |
| 3. 用 WebGPU 做独立图像试验 | 在 HTTPS 的正式识别模块里，用 Web Worker 做批量图像预览、可选清晰度/反光提示；同图比较当前 CPU/Canvas、Worker、WebGPU。可选试验用 ONNX Runtime Web 执行定位组件，但需先查算子、冷启动、张量上传/回读、耗电及输出一致性 | 比较首次及连续操作的端到端耗时、手机稳定性和内存；不只测 GPU 核函数。无可用适配器、设备丢失或未通过输出一致性时走现有路径 |

WebGPU 在安全上下文中开放，正式 HTTPS 部署满足其中一项前提；普通局域网 IP 的 HTTP 不能按默认可用设计。浏览器要以 `isSecureContext`、`navigator.gpu` 和 `requestAdapter()` 实际检测能力。[WebGPU 规范](https://www.w3.org/TR/webgpu/)、[安全上下文规范](https://www.w3.org/TR/secure-contexts/)。

[ONNX Runtime Web 的 WebGPU 说明](https://onnxruntime.ai/docs/tutorials/web/ep-webgpu.html)是端侧试验入口，不代表会加速服务器上的推理。先保留原图和现有服务端识别、审计与结果路径；即使加入客户端质量提示，也不以它更改正式判读。未改生产服务、认证、数据库或识别权重。
