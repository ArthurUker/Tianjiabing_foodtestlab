### 2. 生产部署脚本 (deploy-production.sh)

**功能**:
```bash
脚本流程:
  1. 前置条件检查 (Docker/SSH/curl)
  2. 部署批准确认
  3. 应用构建
     - npm run build:prod
     - Docker 镜像打包
  4. 备份
     - 当前版本备份
     - 数据库备份 (pg_dump)
  5. 部署
     - 上传新文件
     - 停止旧版本
     - 启动新版本
  6. 验证
     - 等待启动 (30 秒超时)
     - HTTP 健康检查
     - API 响应验证
     - 数据库连接检查
  7. 回滚处理
     - 自动检测失败
     - 一键回滚到上一版本
```

**使用**:
```bash
# 演练模式 (不执行实际部署)
./scripts/deploy-production.sh production latest --dry-run

# 实际部署
./scripts/deploy-production.sh production v3.1.0

# 输出
✅ 应用已成功部署到 production
📍 应用地址: http://api.example.com
📝 部署日志: /tmp/deploy-20260424-120530.log
```

**部署策略**: 蓝绿部署

```
当前 (蓝)     新版本 (绿)     切换      监控      清理
   ↓            ↓             ↓        ↓         ↓
[v3.0]  →  [v3.1]  →  50% 流量  →  验证  →  清理旧版本
           部署       验证 5 分钟    30 分钟
           数据库迁移  无异常?      无告警?
           缓存清理   切换 100%     部署完成 ✅
```

## 🔄 部署流程

### 蓝绿部署策略

**优势**:
- ✅ 零停机部署
- ✅ 快速回滚
- ✅ A/B 测试支持
- ✅ 监控友好

**步骤**:

1. **准备绿环境**
   ```
   时间: 5 分钟
   - 构建新镜像
   - 数据库迁移
   - 缓存预热
   ```

2. **灰度发布**
   ```
   时间: 5 分钟
   - 50% 流量 → 绿环境
   - 监控关键指标
   - 确认无异常
   ```

3. **全量切换**
   ```
   时间: 1 分钟
   - 100% 流量 → 绿环境
   - 监控 30 分钟
   ```

4. **验证完成**
   ```
   时间: 即时
   - 清理蓝环境
   - 备份作为新基准
   - 部署记录存档
   ```

### 回滚流程

**自动回滚** (< 30 秒):
```
错误检测
  ↓
自动停止新版本
  ↓
恢复旧版本
  ↓
验证恢复
  ↓
通知团队
```

**条件**:
- 错误率 > 5% 持续 2 分钟
- 响应时间 > 2s 持续 2 分钟
- 应用崩溃 > 1 分钟

**手动回滚**:
```bash
./scripts/rollback.sh
```
