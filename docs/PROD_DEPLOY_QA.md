# 生产环境部署前 · 问答式分析流程

> 用途：在正式部署生产环境（子域名 + HTTPS）之前，逐项确认所有关键决策。
> 方式：每题给出选项（可多选）或"需补充文件"。你作答后，我再输出针对该题的结论与风险提示。
> 原则：本流程**不修改任何代码、不执行任何服务器操作**，仅做分析与确认。

---

## 使用说明
- 每题标记为 `[单选]` / `[多选]` / `[填空]` / `[补文件]`。
- 你只需回复题号 + 选项字母（如 `Q1: B`），或提供补充信息。
- 我会汇总，并在全部答完后给出"可部署 / 需先解决"的最终判定。

## 阶段 0 · 拓扑与目标（决定整体架构）

**Q1 [多选] 你的生产环境子域名打算怎么划分？**
- A. 单子域即可（如 `app.foodtestlab.com` 一套系统）
- B. 多个子域指向**同一后端**（如 `app.x.com` 和 `admin.x.com` 共用 API）
- C. 多个子域指向**不同 IP/机器**（如 `admin.x.com`→机A，`data.x.com`→机B，各跑独立实例）
- D. 暂不打算用子域，仍用 IP+端口

**Q2 [填空] 请列出你计划使用的完整域名（含协议，逗号分隔）：**
> 例：`https://app.foodtestlab.com,https://admin.foodtestlab.com`

**Q3 [单选] 前端（静态页面）与后端 API 的部署关系？**
- A. 同机同域（前端由后端或同机 Nginx/Caddy 提供）
- B. 前后端不同子域（前端 `app.x.com`，API `api.x.com`）
- C. 前端走 CDN/对象存储，后端独立子域

**Q4 [单选] 生产是否启用 HTTPS？**

- B. 否，仍用 HTTP（仅内网/测试）

**Q6 [多选] CORS_ORIGIN 需要包含哪些 Origin？（代码拒绝 `*` 且缺失时回退 localhost）**

- B. 含多个子域（需逗号列出全部）

> 注意：若 Q1 选了 B/C 且后端共用，必须在此把**所有**前端 Origin 写全，否则跨域失败。
