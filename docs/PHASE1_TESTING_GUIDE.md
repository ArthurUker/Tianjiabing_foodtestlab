# Phase 1 功能测试指南

## 概述

本文档提供详细的测试步骤，以验证 Phase 1 优化中新创建的工具类和集成改进是否在实际应用中正常运行。

---

## 🧪 测试环境要求

- 浏览器: Chrome/Firefox/Safari (最新版本)
- 网络: 需要连接到互联网 (部分网络测试需要)
- 文件: 完整的 Tianjiabing_foodtestlab 项目

---

## 📝 测试清单

### 1️⃣ FormValidator 功能测试

#### 测试 1.1: 必填字段验证
**场景**: 在 GenericTest.js 模块进行测试

```步骤:
1. 打开食品安全检测系统
2. 进入 "食堂餐具检测" 模块 (或其他 CRUD 模块)
3. 不填写任何内容，直接点击 "提交" 按钮
4. 观察结果:
   ✅ 应该看到红色错误提示
   ✅ 错误信息应该说明哪些字段是必填的
   ✅ 数据不应被提交
```

#### 测试 1.2: 日期验证
**场景**: 测试日期不能为未来时间

```步骤:
1. 在检测日期字段选择一个未来日期 (例如: 2099-01-01)
2. 填写其他必填字段
3. 点击 "提交" 按钮
4. 观察结果:
   ✅ 应该看到错误提示: "日期不能为未来时间"
   ✅ 数据不应被提交
```

#### 测试 1.3: 验证错误显示
**场景**: 验证错误在表单中的显示效果

```步骤:
1. 不填写任何字段，提交表单
2. 观察结果:
   ✅ 错误应该显示在对应的表单字段下方
   ✅ 错误文字应该用红色显示
   ✅ 每个字段最多显示一个错误消息
```

---

### 2️⃣ UINotification 功能测试

#### 测试 2.1: 成功通知
**场景**: 成功提交数据后看到成功通知

```步骤:
1. 在任何 CRUD 模块中填写有效数据
2. 点击 "提交" 按钮
3. 观察结果:
   ✅ 右上角应该显示绿色成功通知 (带✅)
   ✅ 通知应该在 3-4 秒后自动消失
   ✅ 页面应该刷新显示新数据
```

#### 测试 2.2: 错误通知
**场景**: 操作失败时看到错误通知

```步骤:
1. 在 BackupRestore (备份恢复) 模块
2. 点击 "从服务器恢复数据"
3. 如果网络连接失败，观察结果:
   ✅ 右上角应该显示红色错误通知 (带❌)
   ✅ 错误消息应该清晰说明发生了什么
   ✅ 通知应该显示更长时间 (4-5 秒)
```

#### 测试 2.3: 确认对话框
**场景**: 删除记录时看到现代化确认对话框

```步骤:
1. 在任何模块的数据表中找到一条记录
2. 点击该记录的 "删除" 按钮
3. 观察结果:
   ✅ 应该显示一个现代化的模态对话框 (不是浏览器 alert)
   ✅ 对话框应该有清晰的警告信息
   ✅ 应该有 "确认" 和 "取消" 按钮
   ✅ 点击 "取消" 应该关闭对话框，不删除数据
   ✅ 点击 "确认" 应该删除数据并显示成功通知
```

#### 测试 2.4: 警告通知
**场景**: 用户进行危险操作时看到警告

```步骤:
1. 在 BackupRestore 模块
2. 点击 "清空本地缓存" 按钮
3. 观察结果:
   ✅ 应该显示确认对话框，带有黄色警告标志
   ✅ 消息应该强调操作的不可逆性
   ✅ 对话框应该有两个选项
```

---

### 3️⃣ NetworkHelper 功能测试

#### 测试 3.1: 网络状态监听
**场景**: 测试网络连接检测

```步骤:
1. 打开浏览器开发者工具 (F12)
2. 进入 "网络" 标签页
3. 在应用中进行任何网络操作 (例如: 恢复数据)
4. 观察浏览器控制台:
   ✅ 应该看到网络请求
   ✅ 如果请求失败，应该有自动重试 (最多 3 次)
   ✅ 每次重试之间应该有延迟 (指数退避)
```

#### 测试 3.2: 超时控制
**场景**: 测试请求超时处理

```步骤:
1. 在浏览器开发者工具中限制网络速度 (Slow 3G)
2. 尝试从服务器恢复数据
3. 观察结果:
   ✅ 如果请求超过 10 秒，应该自动重试
   ✅ 重试失败后应该显示错误通知
   ✅ 不应该导致页面卡死
```

---

### 4️⃣ 模块集成测试

#### 测试 4.1: GenericTest.js 集成
**场景**: 测试食堂/农药/油品等通用测试模块

```步骤:
1. 进入 "食堂餐具检测" 模块
2. 测试表单验证:
   - 不填写日期，提交 → 应该显示错误
   - 选择未来日期，提交 → 应该显示错误
   - 填写正确数据，提交 → 应该显示成功
3. 测试删除操作:
   - 点击删除按钮 → 应该显示确认对话框
   - 点击取消 → 数据保留
   - 点击确认 → 显示成功通知，数据删除
```

#### 测试 4.2: Pathogen.js 集成
**场景**: 测试病原体检测模块

```步骤:
1. 进入 "病原体检测" 模块
2. 尝试导入一个 Word 文档 (.docx)
3. 如果文档格式不正确:
   ✅ 应该显示详细的错误消息 (不是简单的 "格式错误")
   ✅ 应该说明期望的文档格式
4. 如果导入成功:
   ✅ 应该显示成功通知，包含导入的数据摘要
   ✅ 新数据应该立即显示在表格中
```

#### 测试 4.3: BackupRestore.js 集成
**场景**: 测试数据备份和恢复

```步骤:
1. 进入 "数据备份与恢复" 模块
2. 点击 "下载备份":
   ✅ 应该生成 JSON 文件
   ✅ 应该显示成功通知，显示导出的记录数
3. 点击 "清空本地缓存":
   ✅ 应该显示确认对话框
   ✅ 对话框应该强调不可逆性
   ✅ 确认后应该显示成功通知，然后刷新页面
4. 从服务器恢复:
   ✅ 应该显示确认对话框
   ✅ 恢复过程应该有进度提示
   ✅ 恢复完成后显示成功通知
```

#### 测试 4.4: Dashboard.js 集成
**场景**: 测试数据看板导出功能

```步骤:
1. 进入 "数据看板" 页面
2. 点击 "导出为 PDF" 按钮
3. 观察结果:
   ✅ 应该显示 "正在生成 PDF，请稍候..." 通知
   ✅ 生成过程中应该显示进度
   ✅ 完成后应该显示成功通知并下载 PDF
   ✅ 如果 PDF 库未加载，应该显示警告通知
```

## 🔍 调试技巧

### 在浏览器控制台中查看工具类

```javascript
// 查看 FormValidator 规则
console.log(FormValidator.rules);

// 测试验证
const data = { testDate: '2024-01-01', inspector: 'John' };
const errors = FormValidator.validate(data, { testDate: ['required'] });
console.log(errors);

// 测试通知
UINotification.success('测试成功消息');
UINotification.error('测试错误消息');

// 测试网络请求
NetworkHelper.get('/api/test').then(data => console.log(data));
```

### 查看网络请求

1. 打开 F12 开发者工具
2. 进入 "网络" 标签页
3. 查看所有 API 请求
4. 查看重试次数和响应时间

### 查看浏览器控制台错误

1. 打开 F12 开发者工具
2. 进入 "控制台" 标签页
3. 查看任何 JavaScript 错误
4. 查看调试信息
