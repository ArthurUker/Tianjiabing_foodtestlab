## 第一部分:P0 失败项复测(负责人:吴翠楠;核心,必须附证据)

### 复测 1:Q1 复检显示异常(优先级最高)

> **首轮疑点**:阶段A"复检合格依旧显示不合格";阶段B/C"无显示复检结果,不管结果是否合格"——两处表述矛盾,
> 且**无 Network 记录**,无法区分"复检根本没保存"还是"保存了但渲染没更新"。
> **本轮关键**:用三阶段法 + **强制抓 Network 提交请求**,一次定位。

**步骤**:
1. 打开 `http://111.231.166.161:8080/tjb/login.html`,用 tjb manager 登录
2. 进入**果蔬农残** → 新增一条记录,检测项目任选,结果选**不合格**,保存
3. 打开该记录**复检入口** → "整改与复检管理"弹窗 → 切"复检录入" tab
4. **先开 F12 → Network 面板**,复检结果选**合格**,填说明,点"提交复检结果"
5. 依次观察(记录每一阶段主列表"检测结果"列的值):

| 阶段 | 操作 | 若"合格" | 若仍"不合格" |
|---|---|---|---|
| A | 提交后**不刷新**直接看 | 渲染正常 | 渲染层问题(需截列表+console) |
| B | **F5 刷新**再看 | 前后一致✓ | 数据未持久化 → **抓提交请求 response body**(关键证据) |
| C | 切菜单再切回 | 前后一致✓ | 缓存未失效(LocalStorage 记录 JSON) |

6. **必抓证据**:Network 面板中"提交复检"请求的 **request body + response body** 完整截图。
   - 若请求**未发出**(Network 无记录)→ 前端事件/校验拦截,截 console
   - 若请求 4xx/5xx → 截响应
   - 若 2xx 但列表不变 → 渲染层,截列表 + 该记录在 LocalStorage(`records__pesticide`)的 JSON
7. 对**肉蛋农残**、**食品油品质**重复 2-6

**判定标准**:阶段B刷新后列表正确=通过;任一阶段异常需带证据反馈。

### 复测 2:V8 保存按钮无反应(基本信息 + 界面定制)

> **首轮疑点**:两个保存按钮均失败,无任何反馈。需区分"点击没触发 JS"vs"请求发出但失败"。

**步骤**:
1. `admin-schools.html` → 学校 tjb → 「基本信息」tab
2. 修改任意字段制造"已修改"状态
3. **先开 F12 → Console + Network 面板**,点「保存修改」
4. 记录:
   - Console 有无**红色报错**(完整复制)
   - Network 有无 `PUT/PATCH /api/admin/schools/tjb` 请求?
     - 无请求 → 事件未触发(截按钮 HTML 区域)
     - 有请求 4xx/5xx → 截响应 body
     - 有请求 200 但无成功提示 → 前端提示逻辑问题
5. 切「界面定制」tab,改任意内容 → 同样流程点「保存定制」

**判定**:请求 200 + 成功提示 = 通过。

## 第四部分:备份模块验证(负责人:曾水平;新增,P0/P1)

> 入口:`admin-schools.html` → 「运维备份」Tab(仅平台超管可见)
> ⚠️ 影子恢复请**先选独立测试学校**(建议 hqyz/dmyz,勿用 tjb),勿在生产正式学校上验证;备份文件含敏感数据勿外泄。
> 需服务器 SSH 权限(B9 检查),以及 tjb 之外任一测试学校的 manager 账号用于恢复后数据核对。

### B1 Tab 可见性
- 超管登录:Tab 出现 ✅;manager 登录:Tab **不出现**(若出现→权限缺陷)

### B2 备份列表
- 打开 Tab:表格显示(时间/类型/学校/大小/校验/操作);Network `GET /api/admin/backups` 200

### B3 立即备份全部
- 点「立即备份全部」→ 确认 → 提示"备份完成:all-databases.xxx.sql.gz.aes";列表出现新记录(类型=全库,校验=已验证)

### B4 单校备份
- 学校下拉选 tjb → 「单校备份」→ 提示"备份完成:school_tjb.xxx.sql.gz.aes";列表出现单校记录
- 若下拉空 → 查 `GET /api/admin/schools`

### B5 离线验证
- 对任一备份点「验证」→ 弹窗:解密/通过,sha256/一致,gzip/解压成功,表数/一致 → 列表状态变「已验证」
- 若「表数:不一致」→ 该备份不完整,**禁止恢复**,反馈开发

### B6 下载
- 点「下载」→ 弹窗选"确定" → 下载 `.aes`(密文,与 meta.json 配对)
- 再点「下载」→ 弹窗选"取消" → 提示"明文下载默认禁止…"(403)——**预期行为**,非缺陷

### B7 影子恢复(重点,危险)
> 前置:先在 tjb 改动一条记录(制造可识别差异)→ 用 B4 的单校备份恢复,验证回滚。

1. 对 tjb 单校备份点「恢复」→ 模态弹出
2. 确认词输入错误值(如 `restore`)→ 执行 → **提示"确认词必须为 RESTORE",不执行**(负向)
3. 输入 `RESTORE` → 执行 → 二次确认 → 按钮"恢复中…" → 弹窗显示 `PREPARING→STAGING→VALIDATING(行数校验通过)→SWITCHING(原子切换)→COMPLETE`
4. 登录 tjb 核对:改动数据**已回到备份时状态**
5. (SSH 侧)确认旧 schema 保留:`psql -c "SELECT nspname FROM pg_namespace WHERE nspname LIKE 'school_tjb_old_%'"`,确认后 `DROP SCHEMA "school_tjb_old_<ts>" CASCADE` 清理

**失败态预期**:恢复中断应提示失败且原数据不受影响(临时 schema 自动清理)。

### B8 维护模式(可选,需运维配合)
- 服务器设 `READONLY_MODE=true` 重启后:写操作返回 503"系统维护中";读操作正常。验证后恢复

### B9 SSH 侧检查(服务器执行)
```bash
systemctl list-timers | grep backup        # 应存在 foodtestlab-api-backup.timer(每日 02:00)
ls -la /var/backups/foodtestlab/<YYYY-MM-DD>/   # 目录 700、文件 600
# 失败告警:临时删密钥触发一次备份,查 public.SystemLog 的 SECURITY:BACKUP_FAILED
```
