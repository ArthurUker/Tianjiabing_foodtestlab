## 使用说明

- **测试账号**:需超管(admin)与某学校 manager 各一。若现有账号密码不便,请联系平台超管重置或临时创建。
- **涉及学校代码**:本文档以 `tjb`(珠海市田家炳中学)为例,可替换为任一学校代码(hqyz / zhyz / shiyan / dmyz)。
- **记录方式**:每项验证请记录「实际结果」,如与「预期结果」不符,请截图 + 打开浏览器开发者工具 Network 面板记录相关请求的 request/response body。
- **完成后反馈**:将结果(通过/失败项 + 截图 + Network 记录)反馈给开发,便于定位。

## 第一部分:Q1 复现(重点,需抓 Network)

> 背景:工单反馈「检测项目填不合格后,复检填了合格,显示还是不合格」。代码排查未定位,需真实复现。

### 步骤 1:登录

1. 打开 `http://111.231.166.161:8080/tjb/login.html`
2. 用 **tjb 的 manager 账号**登录

### 步骤 2:录入一条初检"不合格"记录

1. 左侧菜单进入 **果蔬农残**
2. 点击"新增"录入检测点位:
   - 日期、食堂、检测员必填
   - 检测项目(batchNo)选任一(如"克百威-胶体金检测卡")
   - **结果选"不合格"**
3. 保存

### 步骤 3:进入复检流程,复检选"合格"

1. 找到刚录入的"不合格"记录,点击其**复检入口**(通常在记录详情/操作中)
2. 打开"整改与复检管理"弹窗 → 切到"复检录入"tab
3. 复检结果下拉**选"合格"**
4. 填写复检说明(必填)
5. **先打开浏览器开发者工具(F12)→ Network 面板**(保持记录),再点"提交复检结果"

### 步骤 4:重点观察 4 处(提交复检后,**先不刷新**观察)

| 观察点 | 具体位置 | 预期(正常) |
|--------|---------|-----------|
| ① 主列表状态列 | 该记录"检测结果"列 | 复检合格后应变为「合格」(绿) |
| ② 复检历史展开区 | 弹窗内"已录入的复检记录" | 新提交记录显示「复检合格」 |
| ③ Network 响应 | 复检提交请求的 **response body** | 完整记录,含 `isPassed` / `result` 字段值 |
| ④ 错误提示 | 页面 alert / 提示 | 不应有"请输入复检说明"等拦截 |

### 步骤 4.5(本版新增):刷新/切 Tab 对比定位法

提交复检后,按以下顺序操作并**记录每一阶段 ① 的显示值**,以区分两层根因:

| 阶段 | 操作 | 若①显示"合格" | 若①仍显示"不合格" |
|------|------|--------------|------------------|
| 阶段A | 提交复检后**不刷新**,直接看列表 | 渲染正常,继续阶段B | 渲染层问题(见反馈要求·情形2) |
| 阶段B | 按 **F5 刷新页面**,再看列表 | 前后一致✓(全部正常) | 数据未持久化(见反馈要求·情形1) |
| 阶段C | 切到其他菜单再切回本模块,再看列表 | 前后一致✓(全部正常) | 缓存未失效(见反馈要求·情形3) |

同时打开开发者工具 → **Application → Local Storage** 面板,找到当前学校键(`auth_token__tjb` 旁同域的 `records__pesticide` 或类似键),
展开该记录 JSON,核对 `result` 字段是否已为 `"合格"`(若已为"合格"但列表仍显示不合格 → 渲染层;若仍为"不合格" → 本地缓存未更新)。

### 步骤 5:三模块重复验证

对 **肉蛋农残**、**食品油品质** 重复步骤 2-4.5,确认三个模块行为一致。

### 反馈要求(按情形反馈,便于开发精确定位)

- **情形1(数据未持久化)**:阶段B刷新后①仍"不合格",且 Network 响应 isPassed=true → 反馈:复检提交请求的 **response body 完整复制** + 阶段B截图
- **情形2(渲染层问题)**:阶段A提交后①即"不合格",且 Local Storage 中 result 已为"合格" → 反馈:阶段A截图 + 列表渲染相关 console 输出
- **情形3(缓存未失效)**:阶段B刷新后①变"合格"但阶段C切菜单后又"不合格" → 反馈:Local Storage 该记录完整 JSON + 切菜单前后截图

## 第二部分:前端功能验证清单

### 验证 1:Q4 界面定制-新增检测项目显示

**角色**:平台超管 + tjb manager

1. 平台超管打开 `http://111.231.166.161:8080/admin-schools.html` → 选择学校 tjb → 「界面定制」tab
2. 选「肉蛋农残检测」模块 → 新增一个检测项目,命名为 **"验证项X"** → 保存定制
3. 用 tjb manager 登录,进入 **肉蛋农残检测** 录入页
4. 点"新增点位",展开检测项目下拉

**预期**:下拉中出现"验证项X";**同时原有的默认选项(恩诺沙星/氟苯尼考/克百威等)仍然存在,未被覆盖**
5. 对 **果蔬农残** 模块重复 1-4(预期新增项出现,默认选项保留)

### 验证 2:Q6 停用/启用用户

**角色**:平台超管

1. 打开 `admin-schools.html` → 学校 tjb → 用户管理
2. 对任一非 manager 用户点「停用」
3. 确认弹窗 → 观察提示与列表状态

**预期**:提示"用户已停用",列表该用户状态变「停用」;再次点「启用」→"用户已启用",状态变「启用」。**无报错弹窗**

### 验证 3:N1 检测频率与月报页

**角色**:tjb manager

1. 登录后左侧菜单点 **检测频率与月报**
2. 观察页面

**预期**:显示「检测频率与月报」标题 + 蓝框说明;若有周频次不达标的项目显示红色警告卡,否则绿色"均达标"卡;下方有月报统计表(本月/上月/环比/周目标/本周进度)与近 6 个月趋势折线图(毛玻璃质感,与餐具/病原体模块风格一致)

### 验证 4:N2 检测日历与频率设置页

**角色**:tjb manager

1. 左侧菜单(管理组)点 **检测频率与日历设置**
2. 修改某项目每周目标次数(如餐具 5→6)→ 点「保存阈值」
3. 勾选/取消某日历项 → 点「保存日历」

**预期**:两次保存均提示成功;重新进入页面后修改内容保留

### 验证 5:N2 每日登录提示

**角色**:tjb manager

1. 确认 tjb 的检测日历中**今天(星期几)安排了检测项目**(默认周一餐具/周二农残/周三油/周四肉蛋/周五病原)
2. 若今天有安排:重新登录 tjb

**预期**:登录后约 1.2 秒,右上角弹出"今日待检测:xxx"(对应今天安排的项目);当天只提示一次(刷新不重复弹)

### 验证 6:P8 登录页帮助中心

**角色**:任意

1. 打开任一登录页(如 `http://111.231.166.161:8080/tjb/login.html` 或超管登录页)
2. 点「需要帮助?」

**预期**:跳转到帮助中心页面,含账号与登录 / 系统使用 / 检测频率与月报 / 联系我们 四块内容;页尾有"返回登录"链接可回

**本版新增:子路径部署检查(定位 S2-3 帮助链接无反应)**

1. 在**学校子路径**登录页(如 `http://111.231.166.161:8080/tjb/login.html`)上,右键「需要帮助?」→ 复制链接地址
2. 核对链接地址:应为 `http://111.231.166.161:8080/tjb/help.html`(**相对路径**,含 `tjb/`)
   - ❌ 若显示为 `http://111.231.166.161:8080/help.html`(绝对路径,无 `tjb/`)→ 说明未加载到最新代码(硬刷新后重试),或相对路径修复未生效,请反馈
3. 点击链接,浏览器地址栏应落在 `.../tjb/help.html` 且正常显示帮助中心(HTTP 200)
   - ❌ 若地址栏是 `.../help.html` 且 404/无反应 → 反馈:该链接地址 + 部署路径说明

### 验证 7:Q5 超管登录页"我是学校管理员"

**角色**:平台超管

1. 打开超管登录页 `http://111.231.166.161:8080/super-admin-login.html`
2. 点「我是学校管理员 / 检测员 / 访客?前往普通登录」→ 出现学校代码输入框
3. 输入 **tjb** → 点「进入」

**预期**:跳转到 `login.html?school=tjb`,**不出现**"未识别到有效的学校登录入口"红字,正常显示登录表单
4. **负向测试**:输入非法字符(如 `TJB123` 含大写、或 `tjb#`)→ 点进入

**预期**:输入框红框提示"学校代码仅含小写字母/数字/连字符",不跳转

**本版新增:按钮点击无反应排查(定位 S2-3 登录入口)**

1. 若步骤 2 点击「我是学校管理员...」后**无任何反应**(输入框未出现):
   - 打开开发者工具(F12)→ Console 面板,查看是否有红色报错信息 → 截图反馈
   - 检查按钮区域是否被其他元素遮挡(点击命中了别的层) → 反馈截图
2. 若输入框正常出现,但步骤 3 点「进入」无跳转:
   - Console 查看是否有报错(如 `schoolCode 未定义` / `extractSchoolCode is not a function`) → 反馈
   - Network 面板查看是否有 `GET login.html?school=tjb` 请求及其响应

### 验证 8(本版新增):界面定制-保存修改无反应(S2-7)

**角色**:平台超管

> 背景:工单反馈"界面定制点击保存修改未有反应"。代码层已核实 saveBasicBtn(基本信息保存)与 saveCustomBtn(定制保存)绑定完整,需浏览器端采集未捕获异常以最终定位。

**步骤 1:基本信息「保存修改」**

1. 打开 `admin-schools.html` → 选择学校 tjb → 「基本信息」tab
2. 修改任意字段(如食堂名称末尾加个空格再改回,制造一次"已修改"状态)
3. **先打开 F12 → Console 面板**(保持记录),再点「保存修改」按钮(页面中部)

**预期**:按钮短暂出现 loading(如"保存中..."),随后弹出成功提示或绿色 Toast;Console 无红色报错;Network 有 `PUT/PATCH /api/admin/schools/tjb` 请求且响应 200

**步骤 2:界面定制「保存定制」**

1. 切到「界面定制」tab(如登录样式或字段管理)
2. 修改任一内容(如登录页主色)
3. **保持 F12 → Console 打开**,点「保存定制」按钮

**预期**:与步骤 1 相同——loading → 成功提示;Console 无红色报错;Network 有定制保存请求且 200

**反馈要求**:

- 若点击后**完全无任何视觉反馈**(无 loading、无提示、按钮无变化):
  - Console 面板红色报错**完整复制**反馈(这是定位关键)
  - Network 面板确认点击瞬间是否有请求发出(无请求 → 事件未触发或 JS 中断;有请求但 4xx/5xx → 后端拒绝)
- 若**有 loading 但随后无成功提示**:Network 请求的 request/response body 反馈
- 若仅在「界面定制」tab 复现、基本信息正常:反馈"仅定制 tab 复现" + 定制保存请求 body
