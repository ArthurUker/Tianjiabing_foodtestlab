## 2. 关键问题清单（按优先级）

### P0（建议 1-3 天内处理）

1) 前后端接口契约不一致（访客功能不可用风险）

- 现象：前端调用 `/api/guest/*` 与 `/api/guest-export-request/*`，后端当前未实现对应路由。
- 影响：访客注册/登录/申请导出流程会直接失败。
- 证据：`js/services/GuestAuthService.js` 与 `backend` 目录路由实现不匹配。
- 建议：
  - 在后端补齐访客路由（register/login/verify-token/submit/check-permission/my-requests）。
  - 输出统一 OpenAPI 或最小接口契约文档，前后端共同对齐。

2) 同步路由实现形态与主服务不一致且疑似未接入

- 现象：`backend/routes/syncRoutes.js` 使用 CommonJS（`require/module.exports`），后端主服务是 ESM；`server.js` 中也未挂载该路由。
- 影响：同步路由可能从未生效，前端离线同步流程存在“代码看似有、运行实际无”的隐患。
- 建议：
  - 将 `syncRoutes.js` 改为 ESM。
  - 明确路由前缀并在 `server.js` 挂载。
  - 对同步队列落库（当前为进程内 Map/Array，重启即丢失）。

3) 权限服务存在异步/同步混用逻辑缺陷

- 现象：`PermissionService.getCurrentUserPermissions()` 内部 `import()` 异步执行，但函数同步返回。
- 影响：访客权限判断存在短路/误判风险，权限边界不稳定。
- 建议：
  - 统一改为同步路径（移除动态 import），或改为 async API 并全面改调用链。
  - 权限来源以后端签名令牌为准，不依赖本地推断。

4) 多处将核心对象挂到 window，增加篡改面

- 现象：路由实例多次暴露到 `window.router`，并依赖该全局对象做关键流程。
- 影响：调试便利但增加运行时被脚本改写的攻击面；也增加维护耦合。
- 建议：
  - 生产构建禁用全局暴露（仅开发环境保留）。
  - 事件总线或模块注入替代全局共享。

### P1（建议 1 周内处理）

1) 前端 fetch 缺少统一超时/重试/熔断

- 现象：大量直接 `fetch()`，缺少超时控制与一致的错误分类。
- 影响：弱网或后端抖动时，页面可出现长时间等待与状态不一致。
- 建议：封装 `fetchWithTimeout + retry(backoff) + 统一错误码映射`，并在服务层统一接入。

2) 动态 HTML 渲染点较多，缺少统一转义策略

- 现象：大量 `innerHTML` 拼接；虽然大多数来自模板，但部分内容与用户输入或存储数据有交汇。
- 影响：后续需求迭代中易引入 XSS。
- 建议：
  - 建立“默认 textContent，必要时白名单模板”的渲染规范。
  - 新增 `escapeHtml` 工具并在高风险模块（导出、弹窗、列表渲染）先落地。

3) JWT 密钥回退策略不一致

- 现象：不同模块存在不同默认密钥回退值。
- 影响：配置缺失时行为不可预期；潜在安全与排障成本上升。
- 建议：
  - 启动时强制校验 `JWT_SECRET`。
  - 仅允许开发环境使用固定默认值，并打印高等级告警。

4) 本地存储 JSON 解析仍有若干裸调用

- 现象：部分 `JSON.parse` 没有安全兜底。
- 影响：localStorage 污染时导致功能中断。
- 建议：统一 `safeJsonParse(value, fallback)` 并替换裸调用。

### P2（建议 2-4 周内处理）

1) 可观察性不足

- 建议补齐请求 traceId、关键业务日志分级、慢请求统计与错误聚合。

2) 代码重复与职责边界可继续收敛

- 建议逐步将鉴权、参数验证、错误响应抽成中间件/工具层，减少散落在路由中的重复逻辑。

3) 自动化测试覆盖偏弱

- 建议增加：
  - 后端：鉴权、权限、记录幂等、批量 upsert、冲突处理。
  - 前端：权限守卫、访客流程、导出流程、离线同步关键路径。

## 4. 验收标准

1) 访客功能链路可完整闭环

- 注册 -> 登录 -> 查看权限 -> 发起导出申请 -> 管理端可见。

2) 网络异常可控

- 10s 超时、可重试接口具备指数退避，前端有明确错误提示。

3) 权限判定稳定

- 同一账号在刷新、跨标签页、重新登录场景下，权限结果一致。

4) 同步功能可验证

- 同步路由在生产模式可访问，且重启后不会丢失关键同步状态（至少有持久化日志）。
