# FIX-P2-23：各检测模块合格判断存在顺序依赖脆性

| 字段 | 内容 |
|------|------|

| **优先级** | 🟡 P2 优化 |
| **影响文件** | `js/modules/Tableware.js` |
| **预估工时** | 0.5h |
| **关联问题** | P0-11（合格率 includes('合格') 误判） |
| **状态** | ✅ 已完成（静态验证通过） |

## 1. 问题描述

`Tableware.js` 等检测模块的合格判断依赖"先判断'不合格'提前返回"的代码顺序来保证正确性（`includes('合格')` 会匹配"不合格"子串，必须先排除"不合格"）。这种隐式顺序依赖属维护脆性：未来维护者若调换判断顺序即引入 P0-11 同类缺陷（"不合格"被误判为合格）。

## 2. 根因分析

`js/modules/Tableware.js` L425/L435/L1026 等处原写法：
```javascript
if (result.includes('不合格')) return '...红色';   // 必须先判断
if (result.includes('合格')) return '...绿色';     // 隐式依赖上面的提前返回
```
正确性依赖 `if (不合格)` 在 `if (合格)` 之前，属顺序依赖。P0-11 修复时已将多处改为显式 `&& !includes('不合格')`，但部分残留顺序依赖写法。

## 3. 修复方案（2026-07-04 实施）

统一为显式 `&& !includes('不合格')` 排除写法，消除顺序依赖：

```javascript
// P2-23: 使用显式 && !includes('不合格') 排除，消除判断顺序依赖
if (result.includes('不合格')) return 'fas fa-times-circle';
if (result.includes('合格') && !result.includes('不合格')) return 'fas fa-check-circle';
```

多处（L418-424、L1021-1024 等）统一为显式排除写法，即使调换判断顺序也不会误判。

## 4. 验收标准

- [x] 合格判断均使用 `includes('合格') && !includes('不合格')` 显式排除
- [x] 调换判断顺序不影响正确性（顺序无关）
- [x] 静态验证通过

## 5. 回归测试要点

- [ ] "合格"→绿色，"不合格"→红色，"警戒"→黄色（不受判断顺序影响）

## 6. 备注

- 与 P0-11 同源：P0-11 修复 `includes('合格')` 误判"不合格"的 12 处缺陷，P2-23 消除剩余的顺序依赖脆性，防止维护时重新引入 P0-11 同类 bug。
