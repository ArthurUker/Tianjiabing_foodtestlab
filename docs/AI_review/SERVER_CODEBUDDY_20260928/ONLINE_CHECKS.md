# 线上核验矩阵与停止条件

以下矩阵供服务器 CodeBuddy 在**确认运行版本和权限**后执行。先从当前路由与生产反向代理配置推导真实 URL；表中的路径是仓库代码入口，不保证代理外部路径相同。记录请求 ID、状态码和非敏感字段，不保存响应中的个人数据、cookie、token 或授权密钥。

| 顺序 | 核验 | 方法与目标 | 通过条件 | 环境/限制 |
| --- | --- | --- | --- | --- |
| 0 | 版本一致 | 本机 `git rev-parse`、进程 cwd/启动参数、发布记录 | 运行代码与预期 SHA 一致；差异先解释 | 只读 |
| 1 | 存活 | GET `/api/health` 或 `/health` | 200，仅证明进程存活 | 只读；不代替就绪 |
| 2 | 就绪 | GET `/api/readyz` 或 `/readyz` | 200、已验证、无 blocker；记录 active/disabled 计数 | 只读；非 200 停止后续写探针 |
| 3 | 迁移与审计 | `node backend/sync-tenant-schemas.mjs --check`；`node backend/scripts/006_audit_principal_gate.mjs` | 两者 rc=0；台账/结构/主体门禁逐租户全绿 | 先核对 env 指向生产；只读模式 |
| 4 | 未认证边界 | 无 token 的既有受保护租户 GET | 401/403（以当前合同为准），绝不返回业务数据 | 只读；不猜测账号 |
| 5 | 已授权租户读 | 专用可审计账号读取既有测试记录或 `/api/user/me` | 200，school/角色归属正确，无跨租户内容 | 只读；报告仅留计数/校验摘要 |
| 6 | 外部 OpenAPI | 已交付 client 的现有授权状态、成功/403 比率与经协调的只读 `/v1/ping` 等 | 当前调用合同成立；异常 grant 不被审查自动更改 | 先观察日志；真实对外调用需协调窗口 |
| 7 | 导出与备份元数据 | 管理端只读列举/任务状态；目录权限 `stat` | 对授权角色可见、非授权不可见；文件路径属预期目录 | 不触发 `/run`、下载或恢复 |
| 8 | 合成写读删 | 专用租户内唯一标记的一小条测试数据，立即回读与清理 | 写/读/删和审计一致；清理后零残留 | 仅已准备专用对象、记录上限和清理方案时执行 |
| 9 | 发布后复核 | 重新执行 0–7，比较部署前后 | 无新 503/403、台账与业务状态一致 | 每次发布独立记录 |

## 立即停止条件

- `readyz` 非 200、`--check` 或 006 非零、租户 API 意外 503、外部授权异常增多。
- 观察到跨租户数据、权限绕过、未解释的数据变更、备份失败或审计缺口。
- 进程版本/环境指向不明，或 CodeBuddy 输出将凭据写入日志/文档。

停止时保留原始错误与时间、实例版本和请求 ID；原始敏感日志留仓外，文档只写脱敏事实。不要通过设置 `AUTO_SYNC_TENANTS=false`、`TENANT_READINESS_ATTESTED`、绕过授权或手动改台账来“变绿”。

## 需离开生产做的验证

迁移从旧状态接入、`--baseline-plan/apply`、M1/M2 失败注入、备份恢复、外部备份注册、跨租户写入/竞争、锁接管、索引/表形状破坏、漏洞扫描和负载测试，都使用隔离克隆。记录备份源时间与脱敏标识、克隆数据库/端口、代码 SHA、每步 rc、恢复前后摘要及实例 down 证据。克隆成功后再评估生产是否需要变更；绝不在生产用破坏性反例证明代码问题。

## 生产更新后的证据

每次线上修复记录：备份是否可恢复、变更 commit、实际部署步骤与执行人、迁移前后台账、`--check`/006 结果、`readyz` 和关键业务 HTTP 结果、外部 OpenAPI 授权/调用状态、回退可行范围。若数据库已前向迁移，回退可能只能退 client/代码而不能逆转 DB；以当前迁移和发布脚本实证为准。
