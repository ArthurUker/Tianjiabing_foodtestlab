### 优先级判断

先处理 **SRV-121/122（线上事故与发布边界）**，再验证 **SRV-111（跨校备份元数据）** 与 **SRV-114（清理脚本误删在用 schema）**。接着是 **SRV-110（按校就绪闸门可能被 body.schoolCode 干扰）**、**SRV-108（baseline 证明截断）**、**SRV-106（已撤销会话可能被心跳复活）**。这些项的潜在影响高于目前静态分级中的部分 P2；是否升级 P1 要看隔离实例反例。`SRV-114` 的 DROP 只能在克隆库用合成 schema 验证；生产只做 dry-run 与只读映射核对。

**不建议把“磁盘链变化时只告警并继续放流量”直接作为 SRV-121 修复。** 它可能掩盖真实的未迁移数据库。优先评审不可变发布目录/原子切换、禁止运行中的生产目录落盘、停服或隔离流量后再切换，以及已运行进程如何绑定其代码与迁移清单。发布脚本的实际顺序和失败恢复需实测，不能只看注释。
