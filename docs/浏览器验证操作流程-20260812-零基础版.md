# 第一部分：吴翠楠 · 业务功能测试

## 测试 1：复检功能（最重要，认真看）

### 测试 1 要做什么

在检测系统里，一条记录先被评为"不合格"，然后测试"复检"功能——把结果改成"合格"后，页面显示应该变成"合格"。

**请严格按照下面步骤做，一步都不要省：**

### 第 1 步：登录

1. 打开 `http://111.231.166.161:8080/tjb/login.html`
2. 输入 tjb 学校管理员账号和密码，点"登录"
3. 登录成功后，页面上应该能看到"果蔬农残"等检测栏目

### 第 2 步：新增一条"不合格"记录

1. 点击页面上的"**果蔬农残**"栏目（蓝色入口）
2. 点击"**新增记录**"按钮（一般在页面右上角或中间，绿色按钮）
3. 填写检测信息：
   - 检测项目：任选一个（比如"农药残留快速检测"）
   - 检测结果：**选择"不合格"**（注意：一定要选不合格！）
   - 其他字段：随意填或留空
4. 点"**保存**"
5. 保存后，下面的记录列表里应该出现这条新记录，结果列显示"**不合格**"（红色）

### 第 3 步：打开复检窗口

1. 在记录列表里找到刚才新增的那条记录
2. 看这行的最右边，有一排小图标按钮，点其中"**铅笔/编辑**"样式的图标（鼠标放上去会显示"整改/复检"）
3. 弹出"整改与复检管理"窗口

### 第 4 步：录入复检（关键步骤，仔细看）

1. 在弹出窗口的顶部，有"整改措施记录"和"复检录入"两个标签，**点"复检录入"**
2. 页面会切换，右边能看到"已录入的复检记录"（开始是"暂无复检记录"）
3. 在左边：
   - "**复检结果**"下拉框：**选择"合格"**（默认就是合格，确认一下）
   - "**复检说明**"输入框：**必须输入几个字**，比如输入"复检通过"（⚠️ 不输入会弹提示"请输入复检说明"，这是正常的）
4. 点绿色的"**提交复检结果**"按钮
5. **看到什么算成功**：
   - 弹出提示框"复检结果已保存" ✅
   - 右边的"已录入的复检记录"出现一条**绿色**的"复检合格"记录（带时间和你的说明）✅
   - 关闭窗口后，记录列表里这条记录的结果列变成"**合格**"（绿色）✅

### 第 5 步：三种情况都看一遍

做完第 4 步后，分别做三个动作，每次看记录列表结果列：

| 顺序 | 动作 | 结果列应该显示 |
|---|---|---|
| A | 提交后**不刷新**，直接看列表 | 合格 |
| B | 按 `F5` 刷新页面，再看列表 | 合格（刷新后还是合格） |
| C | 点左边菜单切换到别的栏目，再切回"果蔬农残" | 合格 |

如果三个阶段结果列都是"合格"→ **测试通过**。
如果任何一次显示"不合格"→ 截图，发给开发。

### 第 6 步：其他模块重复

用**同样的方法**（第 2-5 步），再测：
- "**肉蛋农残**"栏目（新增记录 → 选不合格 → 复检选合格 → 看显示）
- "**食品油品质**"栏目（同上）

每个模块都测一遍，共 3 个模块（果蔬、肉蛋、油）。

### 结果怎么填

在测试报告网页上：
- 结果选"✅ 通过"或"❌ 失败"
- "实际表现"写：**三个阶段（不刷新/刷新/切菜单）分别显示什么**，比如"三个阶段都显示合格，正常"或"刷新后变成不合格"
- 失败的必须附截图

# 第二部分：曾水平 · 备份模块测试

## 测试前须知（重要）

- 备份模块入口：超管登录后，打开 `admin-schools.html`，**页面顶部的标签栏里有"运维备份"按钮**，点它进入备份页面
- 备份页面里有：备份记录列表、几个操作按钮
- **请先测 B1-B6，再测 B7；B8 和 B9 需要开发在服务器上操作，见文档最后"需要开发配合的部分"**

## B1：入口权限检查

### 超管视角（做这个）
1. 用**平台超管**登录，打开 `admin-schools.html`
2. 页面顶部标签栏里**能看到"运维备份"按钮** → ✅ 通过
3. 点它，能进入备份页面，看到备份列表 → ✅ 通过

### 非超管视角（做这个）
1. 用 **tjb 学校管理员**（不是超管）账号，直接在浏览器地址栏输入 `http://111.231.166.161:8080/admin-schools.html`
2. **应该**被拦截：整页显示"权限不足"或"仅平台超级管理员可访问"，页面是空的，没有任何按钮和学校列表 → ✅ 通过
3. 如果学校管理员竟然能进入页面、看到学校列表 → ❌ 失败，截图

## B2：备份列表显示

1. 超管进入"运维备份"页面
2. **应该**能看到表格，有"时间 / 类型 / 学校 / 大小 / 校验 / 操作"这几列，里面有几条备份记录 → ✅ 通过
3. 表格是空的 / 页面报错 → ❌ 截图

## B3：立即备份全部

1. 在备份页面，点"**立即备份全部**"按钮
2. 弹出确认框，点"确定"
3. **应该**提示"备份完成"之类，并且列表**最上面出现一条新记录**（类型=全库，校验=已验证）→ ✅ 通过
4. 如果提示失败 / 列表没新记录 → ❌ 截图

## B4：单校备份

1. 在备份页面找到"**学校下拉框**"（选择要备份哪个学校）
2. 下拉框里选一个学校（比如 tjb 或 dmyz）
3. 点"**单校备份**"按钮
4. **应该**提示备份完成，列表出现该学校的单校备份记录 → ✅ 通过
5. 如果下拉框是空的 → ❌ 截图（说明学校列表接口有问题）

## B5：验证备份文件

1. 在备份列表里，找一条记录，点这行的"**验证**"按钮
2. 弹出窗口显示验证结果：解密成功 / 校验一致 / 解压成功 / **表数一致**
3. 四项目都通过，列表状态变成"已验证" → ✅ 通过
4. 如果"表数不一致" → ❌ 截图，**不要继续做恢复测试**

## B6：下载备份文件

1. 在备份列表点一条记录的"**下载**"按钮
2. 弹出窗口问要不要下载，点"**确定**"
3. **应该**下载一个 `.aes` 结尾的文件（密文文件）→ ✅ 通过
4. 再点一次"下载"，这次弹窗点"**取消**"
5. **应该**提示"明文下载默认禁止"之类 → ✅ 通过（这是预期行为，不是 bug）

## B7：恢复测试（影子恢复）

> ⚠️ 重要：恢复测试**不会影响正式数据**，系统是"影子恢复"（先建临时副本，验证通过才切换）。
> ⚠️ 请选一个**独立的测试学校**（比如 hqyz 或 dmyz），不要用 tjb，避免干扰吴翠楠的测试。

### 前置：制造一条可识别数据（必做）

1. 用该测试学校（比如 dmyz）的管理员账号登录
2. 进入任意检测栏目，**新增一条记录**，结果随便选，保存
3. 记住这条记录的内容（比如检测项目、时间）
4. 这条数据就是"备份后新加的"，恢复后它应该**消失**（回到备份时状态）

### 负向测试（故意输错确认词）

1. 超管进入备份页面，找到刚才 B4 备份的**单校备份**记录（dmyz 那个）
2. 点"**恢复**"按钮，弹出恢复确认窗口
3. 输入确认词时，**故意输错**，比如输入 `restore`（小写）
4. 点执行
5. **应该**提示"确认词必须为 RESTORE"（或类似），**没有执行恢复** → ✅ 通过（负向拦截成功）
6. 如果直接执行了恢复 → ❌ 严重问题，截图

### 正向测试（输对确认词）

1. 再点"恢复"，这次输入正确的确认词 `RESTORE`（大写）
2. 点执行，可能需要再点一次确认
3. **应该**看到恢复过程提示：准备中 → 复制中 → 校验中 → 完成
4. 完成后，用 dmyz 管理员登录，进入刚才的栏目
5. **应该**看到：你刚才新增的那条记录**不见了**（被恢复回备份时的状态）→ ✅ 通过（数据回滚成功）
6. 如果记录还在 → ❌ 截图

## B8 和 B9：需要开发配合的部分

**这两项测试人员不用在浏览器操作，由开发在服务器上执行：**

- **B8（维护模式）**：开发会在服务器设置"维护模式"并重启服务，之后你帮忙验证一次：登录页面能不能打开（应该能打开，因为读操作正常）；试着新增一条检测记录，**应该提示"系统维护中"或类似，保存失败** → 这就是正确表现。验证完开发会恢复正常。
- **B9（服务器检查）**：开发直接在服务器上检查备份定时任务、文件权限、失败告警，不需要你在浏览器操作。

**如果你想参与 B8 的浏览器侧验证，请先告诉开发，开发设置好维护模式后通知你，你再登录测试。**
