## 〇、先读我（3 句话版）

1. 系统里有 **5 类账号**，每类账号**看到的菜单不一样、能做的操作也不一样**。这轮就是把每类的「该有的权限」和「不该有的权限」都点一遍。
2. 这轮共 **14 项（P01–P14）**，重点复测之前你反馈过的三个问题：**viewer 能新增检测**、**viewer 能加食用油检测项目**、**修改账户类别失败**。
3. 每做完一项，到 `test-report.html` 上**选结果 + 填实际表现 + 传截图**，点「保存」。

> ⚠️ **最最重要**：测试账号请用**测试学校/测试账号**，不要拿真实在用学校的正式账号乱改角色/删用户。凡是「停用」「删除」「改角色」这类操作，**先截图再点**。

## 一、账号层级总览（先看懂这个表再测）

| 账号类型 | 角色名 | 从哪登录 | 管哪个界面 | 能做什么 | 不能做什么 |
|---|---|---|---|---|---|
| **平台超管** | admin（无学校） | `super-admin-login.html` | 学校管理控制台 `admin-schools.html` | 增/改/停用学校、界面定制、学校用户管理、运维备份、审计日志、管理超管账号 | —（权限最高） |
| **学校主管** | manager | 学校专属登录页 `…/tjb/login.html` | 主界面全部模块 + 「管理」菜单 | 检测记录增删改、导出、用户管理（改角色/停用/启用/重置密码）、审计、访客导出审批 | 进不了学校管理控制台；**不能把用户设成 admin** |
| **检测员** | operator | 同上 | 主界面业务模块 | 查看 + 新增 + 编辑检测记录、导出 PDF | 不能删除记录；看不到管理菜单 |
| **只读用户** | viewer | 同上 | 主界面全部模块（**含病原体**） | 看全部记录 + 导出 PDF | **任何写操作都不能**（新增/编辑/删除） |
| **访客** | guest | 快速访问 / 自助注册 | 主界面只读 + **看不到病原体** | 只读；export_applicant 可提交导出申请 | 写操作、看病原体、默认无导出 |

> **一句话记忆**：超管管学校 → 主管管本校一切 → 检测员只管录入 → 只读用户只能看 → 访客看得最少（没有病原体、没有导出）。

## 三、各用例详细步骤（P01–P14）

### P01 平台超管登录入口隔离

**目的：** 超管只能从超管入口登录，学校账号不能从超管入口登录。

**步骤：**
1. 打开 `super-admin-login.html`，用**平台超管账号**登录 → 应成功进入 `admin-schools.html`。
2. 退出登录，再用 **tjb 的 manager 账号**在这个超管登录页登录。

**判定：** 超管能进管理后台；学校 manager 被拒绝（提示「该账号不是平台超级管理员」）→ 通过。学校账号竟能进超管后台 → 失败并截图。

---

### P02 学校账号访问学校管理控制台被整页拦截

**目的：** manager / operator / viewer 都无权打开学校管理控制台。

**步骤：**
1. 用 tjb 的 manager 登录主界面。
2. 地址栏直接输入 `http://111.231.166.161:8080/admin-schools.html`。
3. 用 operator、viewer 各试一次。

**判定：** 三种学校账号都被整页拦截（显示「仅平台超级管理员可访问」或权限不足、空白页）→ 通过。任一学校账号能进去 → 失败并截图。

---

### P03 主界面左侧菜单按角色显隐

**目的：** 「管理」菜单只有 manager 看得到。

**步骤：**
1. 用 tjb 的 **manager** 登录 → 看左侧导航，应能看到「管理」分组下的：导出数据、备份恢复、用户管理、审计日志、检测频率设置。
2. 分别用 **operator**、**viewer** 登录 → 看左侧导航。

**判定：** manager 能看到全部管理菜单；operator / viewer 看不到「管理」分组 → 通过。operator / viewer 也能看到管理菜单 → 失败并截图（记下各自看到哪些菜单）。

---

### P04 viewer 只读：不能新增检测记录（★核心修复）

**目的：** viewer 是只读账号，不能新增检测记录（对应你之前反馈的「用查看者的账户可以新增检测」）。

**步骤：**
1. 用 tjb 的 **viewer** 登录。
2. 依次进入：餐具洁净度、果蔬农残、食品油、肉蛋农残、病原体检测 5 个模块。
3. 每个模块看有没有「新增 / 保存」入口，有的话点「保存」试着提交一条。

**判定：** viewer 无法新增（新增按钮消失，或点了保存被拒绝、出现「无写入权限」提示、记录没生成）→ 通过。任一模块 viewer 能成功新增 → 失败并截图（含新增成功的记录）。

---

### P05 viewer 只读：不能编辑/删除已有记录

**目的：** viewer 对已有记录没有编辑、删除权限。

**步骤：**
1. 用 tjb 的 **viewer** 登录 → 打开一个**有数据**的检测模块列表。
2. 看每条记录旁有没有「编辑」「删除」按钮，有就点一下试试。

**判定：** viewer 没有编辑/删除按钮，或点击被拒绝（提示无权限、记录没变）→ 通过。viewer 能编辑或删除 → 失败并截图。

---

### P06 viewer 可看全部记录（含病原体）并可导出 PDF

**目的：** viewer 是学校**内部**只读账号，能看全部记录（含病原体）并导出 PDF（这跟访客不一样）。

**步骤：**
1. 用 tjb 的 **viewer** 登录 → 打开「病原体检测」栏目，确认能看到病原体记录列表。
2. 找「导出」功能，试导出 PDF。

**判定：** viewer 能看到病原体 + 能导出 PDF → 通过。看不到病原体或导不出 PDF → 失败并截图。

> 说明：这条专门用来和 P12 访客做对比——访客看不到病原体，viewer 能看。

---

### P07 operator 能新增/编辑但不能删除记录

**目的：** 检测员（operator）能录入、能编辑，但不能删除。

**步骤：**
1. 用 tjb 的 **operator** 登录 → 新增一条检测记录并保存（应成功）。
2. 编辑这条记录再保存（应成功）。
3. 找这条记录的「删除」按钮，看能不能删。

**判定：** 新增 + 编辑成功，且没有删除按钮（或删除被拒）→ 通过。operator 不能新增/编辑，或竟能删除 → 失败并截图。

---

### P08 manager 用户管理：改角色/停用/启用/重置密码生效（★核心修复）

**目的：** manager 在「用户管理」里改角色、停用、启用、重置密码都要生效（对应你之前反馈的「修改账户类别失败」）。

**步骤：**
1. 用 tjb 的 **manager** 登录 → 进「用户管理」。
2. 找一个测试 operator：**改角色为 viewer** → 保存，确认提示成功。
3. **停用**这个用户 → 确认它登录不了；再**启用** → 确认又能登录。
4. **重置**某测试用户密码 → 用新密码登录验证。

**判定：** 改角色、停用、启用、重置密码都生效且登录表现正确 → 通过。改角色报错 / 停用后还能登录 / 重置后新密码无效 → 失败并截图（把填的内容和报错一起截）。

---

### P09 manager 不能授予 admin 角色（提权拦截）

**目的：** 学校 manager 不能把任何人设成 admin（admin 只在平台层，防止跨校越权）。

**步骤：**
1. 用 tjb 的 **manager** 登录 → 进「用户管理」→ 新增/编辑用户，看「角色」下拉框有哪些选项。
2. 如果有 admin 选项，尝试把一个测试用户设成 admin 并保存。

**判定：** 角色下拉里没有 admin 选项，或选了 admin 保存被拒绝（提示「学校账号不可设置为平台管理员」）→ 通过。manager 能成功把人设成 admin → 失败并截图（严重问题）。

---

### P10 角色调整后旧会话实时生效（★核心修复）

**目的：** 后台把用户降级/升级后，该用户**当前已登录的窗口立即生效**，不用重新登录。

**步骤：**
1. 用 tjb 的 **manager** 登录；同时**另开一个无痕窗口**用测试 **operator** 登录并保持打开。
2. manager 把该 operator **降级为 viewer**。
3. 切回 operator 窗口，刷新页面或操作一次（比如试着新增一条记录）。

**判定：** operator 刷新后立即失去写权限（新增被拒 / 菜单变化），无需重新登录 → 通过。降级后 operator 旧会话还能写 → 失败并截图。

> 反向再验一次：把 viewer 升级成 operator，刷新后应**立即获得**写权限。

---

### P11 禁用用户后会话立即失效

**目的：** manager 停用某用户后，该用户已登录的会话立即失效。

**步骤：**
1. 用 tjb 的 **manager** 登录；无痕窗口用测试 **operator** 登录并保持。
2. manager 在「用户管理」里**停用**该 operator。
3. 切回 operator 窗口刷新或操作。

**判定：** operator 刷新后被强制登出 / 提示「账号状态已变更」→ 通过。禁用后 operator 还能正常用 → 失败并截图。

---

### P12 访客快速访问：无病原体模块 + 只读 + 无导出

**目的：** 访客（快速访问/readonly）看不到病原体、只能看、默认没导出。

**步骤：**
1. 打开学校登录页，走「快速访问」入口进入（免凭证）。
2. 看左侧菜单：应**没有**「病原体检测」栏目，也没有管理菜单。
3. 试着新增一条记录，再看有没有「导出」按钮。

**判定：** 无病原体栏目 + 不能新增 + 无导出按钮 → 通过。访客能看到病原体 / 能新增 / 有导出权限 → 失败并截图。

---

### P13 访客自助注册 + 导出申请审批闭环

**目的：** export_applicant 访客能自助注册、提交导出申请，manager 审批通过后获得导出权限。

**步骤：**
1. 登录页走「访客注册」注册一个 export_applicant 访客账号。
2. 用该访客登录 → 提交一条数据导出申请。
3. 用 tjb 的 **manager** 登录 → 找到访客导出申请审批入口 → 批准。
4. 访客重新查看权限 / 导出。

**判定：** 注册成功、申请能提交、manager 批准后访客获得导出权限 → 通过。任一环节失败（注册失败 / 无申请入口 / 审批后仍无导出）→ 失败并截图。

---

### P14 不同学校账号数据隔离（租户隔离）

**目的：** 不同学校账号只能看本校数据，不能跨校。

**步骤：**
1. 用 tjb 的 manager 登录 → 记下 tjb 的检测记录列表。
2. 退出，用另一学校（如 dmyz）的 manager 登录 → 看它的检测记录列表。
3. 对比两校数据是否互相可见。

**判定：** 两校各自只看得到本校数据、互不可见 → 通过。任一账号能看到另一学校的数据 → 失败并截图（严重问题）。

> 手上只有一所学校账号时，可只做「tjb manager 看不到其他学校数据」的单向核对。

## 五、完成标准

- P01–P14 共 14 项全部在 `test-report.html` 填好结果与证据并保存。
- 三个核心修复项必须重点验证并留证据：

  - **P08**（manager 改角色/停用/启用/重置密码）——之前「修改账户类别失败」，这次必须确认修好。
  - **P10 / P11**（改角色 / 禁用后旧会话立即失效）——这是本轮「后台改角色实时生效」的核心修复。
- 所有失败项都附截图证据（含你操作的前后对比）。
