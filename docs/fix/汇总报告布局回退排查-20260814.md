# 浏览器测试汇总报告布局回退问题排查 — 2026-08-14

## 现象

用户连续两次反馈"`docs/test-results/latest/index.html` 页面布局怎么又退回去了？"
截图显示：汇总报告页内容只占屏幕中间一小块（容器宽度 1180px），左右两侧大片粉色渐变空白；
顶部只看到 4 张汇总卡（不是 5 张），且其中两张卡标题都叫"吴翠楠"。

## 根因

1. **`docs/test-results/latest/index.html` 是自动同步的产物**，不是手写文件。
   触发时机：每次有测试结果写入（`POST /api/test-results`）或收口操作（`POST /api/test-results/close`），
   `backend/routes/testResultRoutes.js` 都会 fire-and-forget 调用 `syncTestResultDocs()` 重新生成它。
   手动 `node scripts/sync-test-results-docs.mjs` 也会重新生成。

2. **第一次修宽度时只改了产物文件，没改源文件** —— 当时改了 `docs/test-results/latest/index.html`，
   但没改 `backend/lib/testReportSync.js` 的 `renderHtml()` 模板。
   后续自动同步触发后，旧的源文件又重新生成出 1180px 旧版，把手动改动覆盖了。

3. **第二次修了源文件，但触发同步的写入仍在持续发生** —— 在源代码改动落盘后到下一次同步之间，
   已经保存的测试结果会按"旧源文件"再生成一次 index.html（虽然这次用的是新源文件，
   但中间时序窗口里看到的还是窄版）。再加上浏览器/反向代理可能缓存旧的 CSS，
   用户看到的页面就一直是窄版。

4. **"吴翠楠"重复** —— `renderCards()` 里用 `g.groupName.split(' · ')[0]` 取的是
   "人名"前缀（"吴翠楠 · 业务功能复测..."、"吴翠楠 · 账号权限复测..."），导致两张卡同名。

## 已修复

### 修复 1：宽度自适应（与源代码同步）

`backend/lib/testReportSync.js` 和 `docs/test-results/latest/index.html` 两边一致：

| CSS | 原值 | 新值 | 备注 |
|---|---|---|---|
| `.wrap` | `max-width:1180px` | `max-width:2000px` | 1920~2400px 屏幕基本填满 |
| `.wrap` | `padding:16px 20px 60px` | `padding:16px 28px 60px` | 左右各 28px 避免贴边 |
| `.topnav .container` | `max-width:1180px` | `max-width:2000px` | 导航与主区同宽 |
| `.topnav .container` | `padding:14px 20px` | `padding:14px 28px` | 与主容器对齐 |
| `.cards` | `minmax(260px, 1fr)` | `minmax(220px, 1fr)` | 5 张卡能并排 |
| `.filters` | `padding:18px 22px` | `padding:18px 28px` | 与主容器对齐 |
| `#list` | `minmax(440px, 1fr)` | `minmax(400px, 1fr)` | 2000px 容器里能放 4 列 |

### 修复 2：汇总卡简称

`renderCards()` 改为取 `· ` 之后的部分（"业务功能复测"、"账号权限复测"），
把全名放到 `title` 属性便于悬停查看。

```js
// TD-GnameShort: 汇总卡简称取「· 之后、（之前」的部分
const shortName = g.groupName.includes(' · ')
  ? g.groupName.split(/\s*·\s*/)[1].replace(/\s*（.*$/, '')
  : g.groupName
```

## 给后续维护者的注意事项

**只改源文件** `backend/lib/testReportSync.js` 中的 `renderHtml()` 函数（CSS 在 ` <style>` 块里），
产物 `docs/test-results/latest/index.html` 不要手改 —— 下次任何一条测试结果保存就会自动重新生成，
手改会被覆盖掉。如果只是想立即验证页面，可以先手动同步产物（同步时使用的是当前已修过的源文件），
但下一次保存又会重新生成，所以**最终一定要回到源文件改动才算修好**。

如果用户反馈"页面还是窄版"，按以下顺序排查：
1. 强制刷新（Ctrl+Shift+R / Cmd+Shift+R）跳过浏览器缓存
2. 给 URL 加查询参数 `?_=$(date +%s)` 绕开反向代理缓存
3. 确认 `backend/lib/testReportSync.js` 的 CSS 已经是新值（`grep max-width`）
4. 确认产物 `index.html` 的 CSS 与源文件一致（可能被旧版触发同步覆盖过）
5. 检查是否有定时任务或 cron 在跑 `scripts/sync-test-results-docs.mjs` 而使用的源文件版本不对
