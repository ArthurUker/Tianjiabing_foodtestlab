## 七、第 5 项：B9（SSH 侧检查：定时任务 / 文件权限 / 失败告警）

> ⚠️ **重要说明**：开发已核查，**当前服务器尚未配置每日备份定时任务**（`foodtestlab-api-backup.timer` 不存在）。
> 所以这一项你现在测，结果是「**定时任务缺失**」→ 应如实填「失败」并说明，这是**真实的部署缺口**，不是你的操作问题。
> 下面按三条逐项检查并截图。

### 7.1 检查定时任务
SSH 登录后执行：
```
systemctl list-timers | grep -i backup
```
- ✅ 若出现 `foodtestlab-api-backup.timer` → 定时任务存在，通过
- ❌ 若**没有任何 backup 相关行**（只有系统自带的 dpkg-db-backup 之类）→ 定时任务缺失，**如实记录为失败**

### 7.2 检查备份文件与权限
```
ls -la /opt/foodtestlab/backend/backups/
```
- ✅ 能看到按日期分的目录（如 `2026-08-11`、`2026-08-12`），里面有 `.aes` 文件 → 文件存在
- 检查权限：
```
sudo ls -la /opt/foodtestlab/backend/backups/2026-08-12/
```
- ✅ 目录 700（`drwx------`）、文件 600（`-rw-------`）→ 权限正确
- ❌ 权限过宽（比如 755/644）→ 记录为权限问题

### 7.3 检查失败告警（可选，做不了就跳过）
- 因当前无定时任务，失败告警链路暂无法通过「删密钥触发备份」验证；如开发已修复定时任务，可再执行：
```
journalctl -u foodtestlab-api -n 30 | grep -i backup
```
- 看到备份相关错误日志 → 截图记录

### 填表（B9）
- 结果：❌ 失败（因为定时任务缺失；若权限/文件也异常一并写）
- 实际表现：如实写「服务器未配置每日备份定时任务，备份目录存在但无 timer」
- 证据：上传 `systemctl list-timers | grep -i backup` 的执行结果截图（证明没有 timer）

3. 第一次连接会问 `Are you sure you want to continue connecting?` → 输入 `yes` 回车
4. 提示 `password:` → 输入服务器登录密码（**输入时屏幕不显示任何字符，属正常**），回车
5. 看到 `ubuntu@...:~$` 说明连上了，可以开始复制粘贴上面的命令

- **复制命令**：先选中命令 → `Ctrl+C`（Mac 用 `Cmd+C`）
