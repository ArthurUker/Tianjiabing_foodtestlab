# 病原体设备上报 · 复测检查指导（2026-10-28）

> 用途：现场用真实病毒检测仪（VirusHunter2.0B）上机测试，逐条确认《食品安全检验芯片数据上传问题.xlsx》里反馈的
> 两个问题是否已修复，以及修复后新增的两类「复核提示」是否符合预期。
> 测试范围：**仅在「测试」学校（school_code = `test`）** 进行，不要用真实学校数据。
> 预计耗时：40~60 分钟。

---

## 0. 先明确三条行为口径（避免误判）

| 场景 | 现在的行为 | 为什么这样设计 |
|---|---|---|
| 报文里的食堂名**不在学校食堂名单**里 | **照常入库**（食堂名保留报文原文）+ 打「食堂信息待复核」标记 | 数据不能丢；由管理员判断是"学校确实有这个食堂（需补名单）"还是"检测时填错了" |
| **同一芯片编号**但检测数据不同（不同天 / 同天不同食堂或样本） | **不是重复**：作为**新记录**入库 + 双方都打「芯片编号冲突待复核」标记 | 可能是芯片编号录错，也可能是同一张芯片被重复使用；数据要留住，但关系要人工确认 |
| 同一芯片编号且内容**完全一致**（同一份数据重传） | 200 幂等，不新增记录、不提示 | 网络重试/补传不该产生重复数据 |

另外两条判定口径（与本次报障直接相关）：

- **复测合并只认"同一自然日"**：同一食堂 + 同样本描述 + 同设备 + **同一天** + **不同芯片** → 并入同一档案（检测次数 +1）。
- **样本编号（DetectionNumber）不参与身份判定**：它只是自由文本（数字或文字都行），判断"是不是同一个样本"不看它。

## 1. 复测前准备

1. **设备登记**：超管控制台 →「病原体设备」→ 选中「测试」学校 → 确认你的设备编号（如 `20230914010008`）已登记且在**在用**状态，记下它的「默认食堂」。
2. **密钥**：确认设备上配置的是**统一上传密钥**（请求头 `X-API-Key`）或该设备的专用密钥（以控制台显示为准）。
3. **学校食堂名单**：超管控制台 →「学校管理」→ 测试学校 → 基本信息 → 食堂列表，**先确认当前是「一食堂 / 二食堂 / 三食堂」**（不要提前加四食堂，用例 A1 需要它保持缺失）。
4. **打开控制台**：病原体检测 → 检测记录，**硬刷新一次**（`Ctrl+Shift+R`），确保加载最新前端。
5. 准备一个记录本（或用文末模板），每个用例记下：**设备号 / 芯片编号 / 检测时间 / 上报的样本信息 / 系统显示结果**。

> 提示：设备上报成功后，列表里该行会带 **「设备」** 徽标；点开该行可以看到详情（检测次数、复测轮次、复核横幅）。

### A 组 · 食堂信息（对应报障 ①：填「四食堂」被写成「三食堂」）

## 4. 以下现象**不是 bug**（别误判）

1. **列表里还有旧的合并记录**：2026-10-22 / 10-26 那两条是修复**之前**产生的，本次**不追溯修改**（按你确认"旧数据不用管"）。
2. **A1 一定会出现"待复核"标记**：因为学校食堂名单里确实还没有「四食堂」；A2 配好后就不该再出现。
3. **同芯片换天会产生两条记录**：这是新口径（不是重复），两条都带标记属预期。
4. **极端并发下可能出现 409 `RECORD_BUSY`**：同一档案同时被多张芯片上报时的并发保护，**重试即可**，不会产生重复数据。
5. **检测次数只有详情里有**：列表页只显示日期/食堂/结论，检测次数在详情弹层。

## 5. 附录

### 5.1 错误码速查

| HTTP | 错误码 | 含义 / 处置 |
|---|---|---|
| 200 | — | 成功（可能同时带 `reviewRequired: true`，表示已入库但需人工复核） |
| 400 | `VALIDATION_ERROR` | 报文格式/时间/必填项问题 |
| 401 | `MISSING_KEY` / `INVALID_KEY` | 未带密钥 / 密钥错误或已失效 |
| 403 | `DEVICE_MISMATCH` | 报文设备编号与密钥所属设备不一致 |
| 403 | `DEVICE_NOT_REGISTERED` | 设备编号未登记 |
| 403 | `DEVICE_DISABLED` | 设备已停用 |
| 403 | `DEVICE_BINDING_EXPIRED` | 报文检测时间不在任何绑定期间内（响应附绑定区间） |
| 403 | `IP_DENIED` | 来源 IP 不在白名单 |
| 422 | `CANTEEN_UNRESOLVED` | 样本信息里提取不到食堂名，且设备没配默认食堂 |
| 429 | `RATE_LIMITED` | 超限流（带 `Retry-After`），稍后重试 |
| 409 | `RECORD_BUSY` | 同档案并发更新冲突，重试即可（不产生重复） |

### 5.2 控制台操作路径

- 设备登记 / 改默认食堂 / 变更设备编号：**超管 → 病原体设备**（选学校 → 行内按钮）
- 学校食堂名单：**超管 → 学校管理 → 选中学校 → 基本信息 → 食堂列表**
- 查看记录：**病原体检测 → 检测记录**（列表）→ 点击行看详情

### 5.3 测试数据识别与清理（需 DBA 执行，非必须）

本次复测产生的数据可通过样本描述/食堂名识别。若需要清理：

## 6. 一句话验收标准

> **报障 ①**：报文写「四食堂」，系统就必须显示「四食堂」（+ 待复核提示），绝不出现「三食堂」。
> **报障 ②**：不同天的两次检测必须是**两条独立记录**，各自的结论独立；同一天、同一样本、不同芯片才是复测轮次。
> **新增**：同芯片不同数据 → 入库 + 双向复核提示（含差异明细）；完全相同的重传 → 幂等不重复。
