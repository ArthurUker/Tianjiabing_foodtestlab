0先明确三条判定口径（避免误判）

下面三条是本次修复后的行为，若现场表现与之一致即为「符合预期」，不要当成 bug。

① 食堂名不在学校名单 → 照常入库 + 提示复核
报文写「四食堂」而学校名单只有一/二/三食堂时：食堂仍记「四食堂」，同时打「食堂信息待复核」琥珀标记。不再静默改成默认食堂。
② 同一芯片编号但数据不同 → 不是重复
不同天、或同天不同食堂/样本：作为新记录入库（不并入轮次），两条都打「芯片编号冲突待复核」红标，并列出差异明细。
③ 同一芯片 + 内容完全一致 → 幂等
同一次结果重复上传（网络重试/补传）不新增记录、不提示，返回成功且标记为重复上传。
另外两条判定口径：复测合并只认「同一自然日 + 同食堂 + 同样本描述 + 同设备 + 不同芯片」； 样本编号（DetectionNumber）不参与身份判定（数字或文字都无所谓）。

2用例清单（逐条打勾）

共 15 条：A 组食堂（4）/ B 组同芯片（3）/ C 组合并口径（3）/ D 组防回归（5）。标 核心 的是与报障直接对应的回归点。

A 组 · 食堂信息（对应报障 ①：填「四食堂」被写成「三食堂」）

A1食堂不在名单 → 保留原文 + 待复核核心
操作：样本信息填「四食堂 餐盘涂抹样」，用一张新芯片检测并上传。
预期：
  • 上报返回成功（HTTP 200）；
  • 列表该行食堂显示「四食堂」（不是三食堂 / 一食堂）；
  • 该行出现琥珀色「待复核」徽标；
  • 详情顶部出现琥珀横幅「食堂不在学校食堂名单内（已按原文入库，待复核）」，并给出两条处置路径（补名单 / 更正后重传）。
判定：
A2补进名单后 → 不再提示
操作：超管在「学校管理 → 基本信息」把「四食堂」加入食堂列表；再用另一张新芯片、样本信息仍填「四食堂 餐盘涂抹样」上传。
预期：
  • 入库成功，食堂显示「四食堂」；
  • 没有「待复核」徽标 / 横幅。
判定：
A3样本信息不写食堂 → 回落设备默认食堂
操作：样本信息只写「餐盘涂抹样」（不写食堂），用新芯片上传。
预期：
  • 食堂 = 该设备的默认食堂（准备阶段记下的那个）；
  • 没有「食堂待复核」标记。
判定：
A4关键回归：默认食堂=三食堂时，四食堂仍必须是四食堂核心
操作：把该设备的默认食堂设为「三食堂」，然后重复 A1（样本信息「四食堂 餐盘涂抹样」）。
预期：
  • 食堂仍显示「四食堂」+ 待复核标记；
  • 只要出现「三食堂」即判不通过（这正是原报障的失败模式）。
判定：

B 组 · 同一芯片编号（对应报障 ② 的一半：芯片相同但数据不同算不算重复）

B1完全相同重传 → 幂等
操作：用同一张芯片、完全相同的样本信息与检测时间，把同一次结果再上传一遍（模拟网络重试）。
预期：
  • 返回成功且为「重复上传」语义；
  • 不新增记录（列表条数不变）。
判定：
B2同芯片 · 换一天 → 新记录 + 双向红标核心
操作：记下 B1 的芯片编号；换一天（如今天 → 明天）用同一个芯片编号 + 不同的检测数据上传。
预期：
  • 返回 200（不报错、不拒绝）；
  • 列表新增一条独立记录（不是并入上一条）；
  • 两条记录都带红色「待复核」徽标；
  • 红色横幅写明「同一芯片编号出现不同检测数据（已按新数据入库）」，并列出具体差异（检测日期 / 检测时段 / 阳性项 / CT 值）；
  • 原记录的「检测次数」不增加。
判定：
B3同芯片 · 同天换食堂/样本 → 新记录 + 双向红标
操作：同一天、同一个芯片编号，但换食堂（如四食堂 → 二食堂）或换样本描述后再上传。
预期：
  • 同 B2：新增独立记录 + 双向红色标记（不是并入复测）。
判定：

C 组 · 跨天 / 同日合并（对应报障 ② 的核心：10.26 显示成 10.22）

C1跨天两次检测 → 必须两条独立记录核心
操作：同一设备、同一食堂、同样本描述：第 1 天用芯片甲上传一次；第 2 天用芯片乙再上传一次。
预期：
  • 列表是两条独立记录，各自日期正确；
  • 第 1 天的记录只显示第 1 天的结论（阳性项不被第 2 天覆盖）；
  • 两条的「检测次数」都是 1。
判定：
C2同日复测 → 仍应并入轮次
操作：同一设备、同一食堂、同样本描述、同一天，用芯片丙再做一次并上传。
预期：
  • 并入为复测：详情「检测次数 = 2」；
  • 详情出现「第 2 次检测（复测）」轮次卡片（含芯片号、检测时段、上传时间）；
  • 列表该行结论以最新轮次为准。
判定：
C3样本编号不同不影响合并
操作：同一天、同食堂、同样本描述，但样本编号写得不同（第 1 次填 1，第 2 次填 A-01），用不同芯片。
预期：
  • 仍并入为复测（检测次数 2）——样本编号是自由文本，不参与身份判定。
判定：

3以下现象不是 bug（别误判）

  1. 列表里还有旧的合并记录：2026-10-22 / 10-26 那两条是修复之前产生的，本次不追溯修改（按"旧数据不用管"）。
  2. A1 一定会出现「待复核」标记：学校食堂名单里确实还没有「四食堂」；A2 配好后不应再出现。
  3. 同芯片换天会产生两条记录：这是新口径（不是重复），两条都带标记属预期。
  4. 极端并发下可能出现 409 RECORD_BUSY：同一档案被多张芯片同时上报的并发保护，重试即可，不会产生重复数据。
  5. 检测次数只在详情里：列表页只有日期/食堂/结论，检测次数在详情弹层。

4错误码速查

HTTP错误码含义 / 处置
200—成功（可能同时带 reviewRequired: true：已入库但需人工复核）
400VALIDATION_ERROR报文格式 / 时间 / 必填项问题
401MISSING_KEY / INVALID_KEY未带密钥 / 密钥错误或已失效
403DEVICE_MISMATCH报文设备编号与密钥所属设备不一致
403DEVICE_NOT_REGISTERED设备编号未登记
403DEVICE_DISABLED设备已停用
403DEVICE_BINDING_EXPIRED报文检测时间不在任何绑定期间内（响应附绑定区间）
403IP_DENIED来源 IP 不在白名单
422CANTEEN_UNRESOLVED样本信息里提取不到食堂名，且设备没配默认食堂
429RATE_LIMITED超限流（带 Retry-After），稍后重试
409RECORD_BUSY同档案并发更新冲突，重试即可（不产生重复）

5一句话验收标准

报障 ①：报文写「四食堂」，系统就必须显示「四食堂」（+ 待复核提示），绝不出现「三食堂」。

报障 ②：不同天的两次检测必须是两条独立记录，各自结论独立；同一天 + 同一样本 + 不同芯片才是复测轮次。

新增能力：同芯片不同数据 → 入库 + 双向复核提示（含差异明细）；完全相同的重传 → 幂等不重复。

控制台路径：设备登记/改默认食堂 → 超管 · 病原体设备；学校食堂名单 → 超管 · 学校管理 · 基本信息；查看记录 → 病原体检测 · 检测记录。
